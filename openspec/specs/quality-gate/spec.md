# quality-gate Specification

## Purpose
依据基线、阈值与回归三类条件对一次评测运行做上线准入判定，把「绝对水平够不够」和「比上次差了没有」组合成可自动执行的结论，让退化的提交在合并前被拦住，而不是等到线上暴露。

## Requirements

### Requirement: Baseline capture

系统 SHALL 支持把一次已完成运行捕获为命名基线，记录每个用例的判定状态与来源运行标识。

#### Scenario: 捕获基线

- **WHEN** 用户对一次已存储的运行执行基线捕获
- **THEN** 系统写入该运行的用例状态快照，并可被后续门禁读取

#### Scenario: 基线来源运行不存在

- **WHEN** 用户指定的运行标识不存在
- **THEN** 系统报错并以非零退出码结束，且不写入基线

### Requirement: Threshold evaluation

系统 SHALL 支持按最低通过率与最大错误数两个阈值评估一次运行。

#### Scenario: 通过率低于阈值

- **WHEN** 一次运行的通过率低于声明的下限
- **THEN** 门禁判定为不通过，并在报告中指出实际值与阈值

#### Scenario: 错误数超过阈值

- **WHEN** 一次运行中判定为 error 的用例数超过声明的上限
- **THEN** 门禁判定为不通过，并在报告中指出实际值与阈值

#### Scenario: 运行中没有任何用例

- **WHEN** 被评估的运行不包含任何判定
- **THEN** 门禁判定为不通过，而不是因为通过率为零之外的假象而通过

### Requirement: Regression detection against baseline

系统 SHALL 识别相对基线的回归：基线中通过、当前失败或错误的用例，以及基线中存在、当前缺失的用例。

#### Scenario: 用例由通过变为失败

- **WHEN** 某用例在基线中为通过、在当前运行中为失败或错误
- **THEN** 该用例被列入回归清单，并在报告中逐条列出

#### Scenario: 用例在当前运行中缺失

- **WHEN** 某用例存在于基线，但未出现在当前运行中
- **THEN** 该用例被列入缺失清单，并在报告中逐条列出

#### Scenario: 未提供基线

- **WHEN** 门禁运行时不存在可用基线
- **THEN** 系统仅按阈值评估，并在报告中明确说明未使用基线

### Requirement: Gate decision and exit code

系统 SHALL 依据阈值与回归结论给出通过或不通过，并用进程退出码表达结论。

#### Scenario: 全部门禁条件满足

- **WHEN** 通过率与错误数满足阈值，且不存在回归
- **THEN** 门禁判定为通过，进程退出码为零

#### Scenario: 任一条件不满足

- **WHEN** 阈值不满足或存在回归
- **THEN** 门禁判定为不通过，进程退出码为非零

#### Scenario: 回归被显式豁免

- **WHEN** 用户显式开启允许回归
- **THEN** 回归与缺失不参与门禁结论，但仍被列出在报告中

### Requirement: Gate report

系统 SHALL 产出机器可读与人类可读两种形式的门禁报告，内容 MUST 包含结论、实际指标、阈值与不通过原因。

#### Scenario: 机器可读报告

- **WHEN** 用户以 JSON 形式请求门禁结果
- **THEN** 输出包含结论、用例计数、通过率、阈值、回归清单与缺失清单的结构化数据

#### Scenario: 人类可读报告

- **WHEN** 用户以文本形式查看门禁结果
- **THEN** 输出逐条列出不通过原因，且结论一眼可辨
