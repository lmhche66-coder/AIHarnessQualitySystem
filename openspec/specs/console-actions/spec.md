# console-actions Specification

## Purpose
让控制台从只读展示面变成可操作的工作台：在受控边界内允许从界面产生副作用，首批操作覆盖结论浏览与基线管理，使「哪次运行算基线」这类需要人决定的事情可以在界面上完成。

## Requirements

### Requirement: Conclusion browsing

系统 SHALL 提供结论视图，列出结论记录并按类型展示摘要，分别覆盖门禁、失败归因与裁判校准。

#### Scenario: 列出结论

- **WHEN** 结论目录中存在记录
- **THEN** 界面按时间倒序列出，每条显示类型、结论与创建时间

#### Scenario: 展示门禁结论

- **WHEN** 选中一条门禁结论
- **THEN** 界面展示其来源运行、通过率、失败与错误数、回归与缺失的数量

#### Scenario: 展示归因结论

- **WHEN** 选中一条失败归因结论
- **THEN** 界面展示失败总数、可回流数、已验证数与候选用例数量

#### Scenario: 展示裁判校准结论

- **WHEN** 选中一条裁判校准结论
- **THEN** 界面展示样本数、一致率、置信区间、位置翻转率与长度偏好比例

#### Scenario: 没有结论

- **WHEN** 结论目录为空
- **THEN** 界面显示空状态并说明产生结论的命令，而不是报错

### Requirement: Baseline management

系统 SHALL 提供基线视图，列出已有基线，并支持把一次运行捕获为命名基线。

#### Scenario: 列出基线

- **WHEN** 存在已保存的基线
- **THEN** 界面展示其名称、来源运行、用例数与状态分布

#### Scenario: 捕获基线

- **WHEN** 用户选择一次运行并给出基线名
- **THEN** 系统把该运行捕获为基线，并在列表中可见

#### Scenario: 同名基线被覆盖

- **WHEN** 用户以已存在的基线名再次捕获
- **THEN** 该基线被更新为新的来源运行，而不是并存两条同名基线

#### Scenario: 来源运行不存在

- **WHEN** 用户为不存在的运行捕获基线
- **THEN** 系统报错并指明该运行，且不写入基线

### Requirement: Action boundary

系统的写接口 SHALL 仅在控制台绑定回环地址时可用；绑定到其它地址时，写接口 MUST 被拒绝且读接口不受影响。

#### Scenario: 回环地址下允许操作

- **WHEN** 控制台绑定回环地址且用户发起写操作
- **THEN** 该操作按语义执行

#### Scenario: 非回环地址下拒绝操作

- **WHEN** 控制台绑定非回环地址且用户发起写操作
- **THEN** 系统拒绝该操作并说明原因，读接口仍然可用

#### Scenario: 非法请求体

- **WHEN** 写请求的请求体缺失、不是合法 JSON 或不是对象
- **THEN** 系统以请求错误拒绝，而不是抛出未处理异常

### Requirement: Action auditability

写操作 SHALL NOT 覆盖或删除既有运行记录与结论记录；基线捕获只新增或更新基线文件。

#### Scenario: 捕获基线不影响运行记录

- **WHEN** 用户从界面捕获基线
- **THEN** 运行记录与结论记录保持不变，只有基线文件被写入

### Requirement: Gold set authoring and labeling

系统 SHALL 支持在界面上创建金标集并逐条标注，标注结果 MUST 持久化到运行根目录下的金标目录。

#### Scenario: 创建金标集

- **WHEN** 用户提交一份包含配对样本的金标集
- **THEN** 系统以给定名称写入金标目录，并在列表中可见

#### Scenario: 逐条标注

- **WHEN** 用户为某条样本选择偏好
- **THEN** 该样本的标注被写入金标集文件，且进度随之更新

#### Scenario: 查看进度

- **WHEN** 金标集中存在未标注的样本
- **THEN** 列表展示已标注数与总数

#### Scenario: 提交的样本不合法

- **WHEN** 提交的样本缺少标识、提示词或偏好取值非法
- **THEN** 系统以请求错误拒绝，并指明第几条样本

#### Scenario: 标注不存在的金标集

- **WHEN** 用户标注一个不存在的金标集
- **THEN** 系统报错并指明该名称

### Requirement: Trace upload

系统 SHALL 支持在界面上传工具调用审计文件并导入为命名轨迹，接受 JSON 与 CSV 两种形态。

#### Scenario: 导入成功

- **WHEN** 用户上传一份合法的审计文件并给出轨迹名
- **THEN** 系统保存该轨迹，并返回记录数与保真度限制

#### Scenario: 审计内容不合法

- **WHEN** 上传内容为空、缺少必要字段或参数不可解析
- **THEN** 系统以请求错误拒绝，并指明出错记录的位置

#### Scenario: 缺少轨迹名

- **WHEN** 用户未提供轨迹名
- **THEN** 系统以请求错误拒绝，而不是写入一个无名的轨迹

### Requirement: Failure reflow review

系统 SHALL 支持在界面上对一次运行执行失败归因，并让人工选择哪些可回流失败写入候选用例。

#### Scenario: 展示可回流失败

- **WHEN** 用户对一次运行执行归因
- **THEN** 界面逐条展示失败用例、失败判据与是否可回流及其原因

#### Scenario: 写出被选中的候选用例

- **WHEN** 用户勾选若干条已通过复现自证的失败并提交
- **THEN** 系统把对应的候选用例写入运行根目录下的用例目录，并说明写入数量

#### Scenario: 未选中任何候选用例

- **WHEN** 用户没有勾选任何候选用例
- **THEN** 系统不写出文件，并明确说明没有任何内容被写入

#### Scenario: 缺少原始用例定义

- **WHEN** 归因无法找到该运行对应的原始用例定义
- **THEN** 系统报错并说明需要提供用例文件，而不是给出空报告

### Requirement: Run triggering

系统 SHALL 支持从界面触发一次同步运行，覆盖「契约与过程用例」与「端到端任务集」两种模式，并返回其运行标识与结果。

#### Scenario: 触发成功

- **WHEN** 用户提供用例文件与工具注册表并触发运行
- **THEN** 系统执行该运行、保存运行记录，并返回运行标识与通过失败计数

#### Scenario: 触发任务集

- **WHEN** 用户提供任务集文件、环境工厂与 agent 工厂并触发运行
- **THEN** 系统执行任务集、保存运行记录，并返回解决数与通过率

#### Scenario: 用例文件不存在

- **WHEN** 用户提供的用例文件不存在
- **THEN** 系统以请求错误拒绝并指明该文件

#### Scenario: 注册表无法载入

- **WHEN** 工具注册表无法载入或未返回注册表
- **THEN** 系统以请求错误拒绝并说明原因

#### Scenario: 运行失败不阻断记录

- **WHEN** 触发的运行中存在失败或出错的用例
- **THEN** 运行记录照常保存并返回结果，而不是以请求错误结束

### Requirement: Operation error contract

每个操作 SHALL 在失败时返回可读原因并指明对象；缺少必需输入、目标不存在与内容不合法 MUST 被区分为不同的请求错误。

#### Scenario: 缺少必需输入

- **WHEN** 请求缺少必需字段
- **THEN** 系统返回请求错误并指明缺失的字段名

#### Scenario: 目标不存在

- **WHEN** 请求指向不存在的运行、金标集或轨迹
- **THEN** 系统返回未找到错误并指明该对象

#### Scenario: 内容不合法

- **WHEN** 请求内容无法解析
- **THEN** 系统返回请求错误并给出可读原因，而不是抛出未处理异常

### Requirement: Gate triggering

系统 SHALL 支持从界面对一次已存储的运行执行门禁判定，并把结论写入结论目录。

#### Scenario: 触发门禁

- **WHEN** 用户选定一次运行并触发门禁
- **THEN** 系统执行判定、写入一条门禁结论，并返回通过与否与失败原因

#### Scenario: 引用不存在的基线

- **WHEN** 用户为门禁指定了一个不存在的基线名
- **THEN** 系统以请求错误拒绝并指明该基线，而不是只按阈值判定

#### Scenario: 未指定基线

- **WHEN** 用户没有指定基线
- **THEN** 系统按阈值判定并在结果中说明未使用基线

### Requirement: Judge calibration triggering

系统 SHALL 支持从界面用指定金标集与判定器执行裁判校准，并把结论写入结论目录。

#### Scenario: 触发校准

- **WHEN** 用户选定金标集与判定器并触发校准
- **THEN** 系统执行校准、写入一条校准结论，并返回一致率、置信区间与偏置指标

#### Scenario: 金标集尚未标注

- **WHEN** 金标集中没有任何已标注样本
- **THEN** 系统以请求错误拒绝并说明需要先完成标注

#### Scenario: 部分样本未标注

- **WHEN** 金标集中只有部分样本已标注
- **THEN** 系统只用已标注样本执行校准，并在结果中说明跳过的数量

#### Scenario: 判定器无法载入

- **WHEN** 指定的判定器工厂无法载入或未返回可调用对象
- **THEN** 系统以请求错误拒绝并说明原因
