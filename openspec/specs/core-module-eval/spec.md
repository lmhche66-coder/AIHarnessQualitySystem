# core-module-eval Specification

## Purpose
按感知、规划、记忆、工具四个核心模块采集执行信号并做模块级断言，让每一层的质量可独立观测，而不是只能看到最终回复。

## Requirements

### Requirement: Module execution signals

系统 SHALL 支持把感知、规划、记忆、工具四个核心模块的执行信息写入用例轨迹，并 SHALL 支持按模块抽取这些信号。信号 MUST 以新增的保留事件名落在既有轨迹上，MUST NOT 改变既有事件命名与运行记录格式。

#### Scenario: 记录并抽取模块信号

- **WHEN** 执行期写入感知、规划、记忆或检索信号
- **THEN** 系统按发生顺序抽取到对应模块的信号，并保留其载荷与耗时

#### Scenario: 模块没有信号

- **WHEN** 轨迹中不存在某个模块的信号
- **THEN** 查询该模块返回空，而不是返回其他模块的信号

#### Scenario: 指标归口到模块

- **WHEN** 按模块聚合规格指标
- **THEN** 每个已登记指标映射到唯一模块，未登记指标不归入任何模块

### Requirement: Module-level assertions

系统 SHALL 提供模块级断言，覆盖感知的意图与 Skill 命中、规划的路由决策与工具决策、记忆的短期记忆保留与长期检索召回。断言 MUST 只读取轨迹中的模块信号，并在信号缺失时给出可定位的失败原因。

#### Scenario: 意图与 Skill 命中

- **WHEN** 用例声明期望意图或期望 Skill
- **THEN** 断言比对感知信号中的意图与 Skill，并按声明模式在任一或全部命中时判定通过

#### Scenario: 路由决策

- **WHEN** 用例声明期望路由方向
- **THEN** 断言比对规划信号中的路由方向，并可一并断言选中的工具

#### Scenario: 工具决策

- **WHEN** 用例声明期望工具集合
- **THEN** 断言规划信号中选中的工具按顺序包含期望工具

#### Scenario: 短期记忆保留

- **WHEN** 用例声明应保留的关键信息或最小会话轮数
- **THEN** 断言记忆信号中的注入内容包含全部关键信息，且会话轮数不低于下限

#### Scenario: 长期检索召回

- **WHEN** 用例声明应召回的片段标识或最小片段数
- **THEN** 断言检索信号中的片段覆盖全部期望标识，且数量不低于下限

#### Scenario: 信号缺失

- **WHEN** 某模块级断言没有对应的模块信号可读
- **THEN** 该断言判为失败，并指明缺少哪个模块的信号

### Requirement: Upstream error skips downstream metrics

系统 SHALL 在路由决策断言失败时，把依赖检索证据的下游指标标记为跳过。被跳过的断言 MUST NOT 计入通过、失败或失败断言列表，且 MUST 在按指标聚合时同时从分子与分母剔除。

#### Scenario: 路由误触发

- **WHEN** 路由决策断言失败，且同一用例存在依赖检索证据的下游断言
- **THEN** 该下游断言被标记为跳过，路由错误只体现在路由决策指标上

#### Scenario: 不污染无关指标

- **WHEN** 路由决策断言失败，但某指标不依赖检索证据
- **THEN** 该指标保持原有判定，不被标记为跳过

### Requirement: Module aggregation in the scorecard

系统 SHALL 在记分卡中按模块聚合指标通过率，并如实标注跳过与执行错误不进分母。

#### Scenario: 按模块输出通过率

- **WHEN** 用户对一次运行请求记分卡
- **THEN** 输出按感知、规划、记忆、工具分组的指标通过率，只包含实际出现指标的模块

#### Scenario: 某模块没有指标

- **WHEN** 运行中没有归属到某模块的指标
- **THEN** 记分卡不输出该模块，而不是给出 0 通过率
