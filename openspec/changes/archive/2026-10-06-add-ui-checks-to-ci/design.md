# Design

## Context

- 既有 CI 跑测试、录制回放、门禁、任务、回流、审计导入、裁判校准与压测。
- `ui-checks` 已提供 UI 流程与 Playwright 驱动；`tools/check_console_layout.py` 提供布局不变量检查。两者都只在本地跑过。

## Goals / Non-Goals

**Goals:**

- 界面缺陷在流水线上可见，而不是只在本地可见。
- 增加的时间可接受，主要靠缓存摊薄。

**Non-Goals:**

- 不做视觉回归与截图比对（需要基线图库，是另一件事）。
- 不在 CI 里跑移动端驱动。

## Decisions

### D1 缓存 Playwright 浏览器目录，而不是跳过安装

浏览器二进制约 180MB，是所有方案里最贵的部分。缓存的键包含操作系统与依赖声明文件哈希：依赖没变就命中缓存，只花解压时间；依赖变了才重新下载。
备选：每步都装（每次多两分钟以上）；不装（界面缺陷永远只在本地可见）。

### D2 布局检查与 UI 流程都跑，各管一段

布局检查遍历全部视图与两种视口，验证「渲染正常且不溢出」；UI 流程验证「一条真实用户路径能走通」。前者覆盖面广，后者验证交互链路，缺一不可。
备选：只跑其中一个（分别漏掉覆盖广度与交互链路）。

### D3 检查放在产生数据之后

界面需要真实运行记录才能渲染出有内容的页面。放在流水线靠后，前面各步已经写入了运行、结论与轨迹，检查才有意义。
备选：放在最前（界面是空态，检查等于没检查）。

## Risks / Trade-offs

- [缓存未命中时流水线变慢] → 只有依赖变更时才会发生，且属于一次性成本。
- [浏览器在 CI 里偶发启动失败] → 检查会失败并留下日志；本变更加的是明确的检查步骤，不掩盖失败。
- [布局阈值过硬导致误报] → 阈值留了 2px 余量，并且只检查叶子节点的文本溢出与页面级横向滚动，不追求像素级一致。

## Migration Plan

- 仅流水线配置变更，可整体回滚。
