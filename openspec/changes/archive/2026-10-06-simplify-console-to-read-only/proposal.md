# Proposal

## Why

控制台在演进中长出了两套界面：只读展示与操作工作台。操作入口把「看结论」和「改状态」混在同一个页面里，六分区并列也让人分不清哪个是读、哪个是写。评测的实际触发者是 CLI 与 CI，界面承担写操作只会带来误操作面与维护成本。

## What Changes

- 控制台收敛为只读：界面不再提供任何产生副作用的入口，触发运行、判定门禁、校准裁判、标注金标、上传轨迹、写出回流候选全部移到 CLI 与 CI。
- 分区从六个收敛为四个：运行、结论、基线、资产。资产把金标集、证据轨迹与回流数据集三份只读清单集中呈现。
- 新增只读的回流数据集端点，使 `reflow` 的产出可以在界面上被看见。
- 基线视图保留列表与详情，移除捕获表单。
- 后端写接口保持不变：既有 API、CLI 与 CI 行为不受影响，本次只改界面暴露面。
- **BREAKING**：界面上不再能执行操作；依赖界面点按产出副作用的流程需要改用 CLI。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `console-actions`: 界面收敛为只读四分区；基线管理改为只读；移除界面侧的触发、标注、上传与回流操作要求。

## Impact

- 前端重写为四个只读分区；新增 `AssetsView`，删除三个操作视图。
- `console` 服务新增只读的 `/api/reflow` 端点。
- 布局检查、UI 流与截图工具的视图清单同步更新。
