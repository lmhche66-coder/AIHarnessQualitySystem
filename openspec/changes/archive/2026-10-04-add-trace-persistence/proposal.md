# Proposal

## Why

轨迹级断言已经能跑，但目前只能作用在运行器当场驱动的脚本步骤上。真实 agent 的轨迹既无法落盘、也无法复用，更没法在 CI 里对一份固定轨迹反复复评。断言引擎造好了却没有通电：缺了这段管道，L2 对真实 agent 接不上，也没法把一次真实失败变成可反复执行的回归用例。

## What Changes

- 新增命名轨迹的持久化：把一条轨迹保存到运行根目录下的 traces 目录，支持重新读取与列举。
- 支持从既有运行中提取某条用例的轨迹，并命名为可复用轨迹。
- 支持让过程用例对指定轨迹求值：运行器不再驱动步骤，直接对被引用的轨迹执行过程断言。
- 步骤与外部轨迹同时出现时显式拒绝，避免两个来源被悄悄混用。
- 引用的轨迹不存在时报错并终止，且不写入运行记录。
- 运行记录标注本次使用的轨迹来源，便于归因。
- **BREAKING**：无。既有过程用例、工具契约用例与运行格式不变。

## Capabilities

### New Capabilities

- `trace-persistence`: 命名轨迹的保存、读取、列举与来源标注，以及过程用例对已保存轨迹求值的执行语义。

### Modified Capabilities

- `trace-assertions`: 过程用例的执行来源从「只执行声明的步骤」扩展为「执行声明的步骤，或对一条已保存轨迹求值」，两种来源互斥。

## Impact

- 新增 `agenteval.trace_store` 模块与运行根目录下的 `traces/` 目录。
- CLI 新增 `trace save` 与 `trace list` 子命令；`run` 新增 `--trace` 选项。
- `ContractRunner` 增加外部轨迹求值路径，并在两个来源冲突或缺失时产出显式错误判定。
- 依赖无新增。
- 本变更让「真实 agent 的一次失败」可以被固化成可重复执行的评测资产，也是后续失败样本回流的直接前置。
