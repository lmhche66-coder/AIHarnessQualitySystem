# Proposal

## Why

平台现在能跑出运行记录，但没有任何东西依据这些记录拦住一次退化的提交。上线准入要回答的只有三个问题：有没有基线、有没有阈值、低于阈值能不能自动拦发布。缺了这条闭环，前面所有用例都只是「跑过了」，不是「守住了」。

## What Changes

- 新增质量门禁能力：把一次运行捕获为基线，并按阈值与回归结论对后续运行给出通过或不通过。
- 支持显式阈值：最低通过率与最大错误数。
- 支持回归识别：基线中通过、当前失败或错误的用例，以及基线中存在、当前缺失的用例。
- 门禁结论以进程退出码表达，可直接作为 CI 步骤的成败，不需要额外的解析脚本。
- 产出机器可读与人类可读两种报告，逐条列出不通过原因。
- 新增 GitHub Actions 工作流，串起测试、录制、回放与门禁，让每次提交自动验证。
- **BREAKING**：无。既有命令与运行记录格式不变。

## Capabilities

### New Capabilities

- `quality-gate`: 依据基线与阈值对一次运行做上线准入判定，包括基线捕获、阈值评估、回归识别、退出码语义与报告产出。

### Modified Capabilities

无。门禁只读取既有运行记录，不改变 `eval-core`、`tool-contract-eval` 与 `record-replay` 的任何既有需求。

## Impact

- 新增 `agenteval.gate` 模块，以及运行根目录下的 `baselines/` 目录。
- CLI 新增 `baseline` 与 `gate` 子命令；既有子命令行为不变。
- 新增 `.github/workflows/ci.yml`，把本地可执行的命令原样搬进 CI。
- 依赖无新增，判定逻辑只使用标准库。
- 本变更是后续「在线评测」与「评分阈值」演进的基础，但本变更只做确定性的阈值与回归判定。
