# Design

## Context

- 既有 `e2e-tasks` 的 `AgentRunner` 是「环境 + 任务 → 跑完」的一次性协议，平台在 agent 执行期间没有控制权。See proposal.md - Why。
- `trace-assertions` 已提供工具调用归一化与四类轨迹断言；`record-replay`、`console` 与 `quality-gate` 消费运行记录。
- 硬约束：多轮验证不能要求任何既有接入方改写代码。

## Goals / Non-Goals

**Goals:**

- 平台掌握对话循环，用户消息可编程。
- 每一轮的工具调用可归属，从而支持「先问后做」这类跨轮断言。
- 脚本模拟器完全确定，多轮断言可离线复现。
- 既有一次性任务协议零改动。

**Non-Goals:**

- 不实现 LLM 模拟用户；需要时由使用方以自定义模拟器接入。
- 不做对话的多分支与回溯，一条用例走一条线。
- 不做语音、富媒体与多模态回合。
- 不做对话质量的语义评判，那属于裁判层。

## Decisions

### D1 新增逐轮协议，而不是改造既有协议

`AgentRunner` 是「一次性任务」这件事的准确表达，真实 agent 大多是那个形状。把它改成流式的，等于要求所有既有接入方重写，包括示例、测试与命令行工厂。多轮是一个不同的用法，值得有自己的契约。
备选：改造既有协议（破坏全部既有接入）。

### D2 循环控制权在平台，agent 只负责一轮

只有平台掌握循环，模拟用户才有机会在回合之间插话，跨轮断言才有地方落。agent 退化成「输入对话、输出本轮回复」的函数。
备选：agent 内部循环并在需要时向外部索取用户输入（控制反转困难，断言无处安放）。

### D3 用户消息由模拟器的返回值决定，空值即结束

模拟器返回 `None` 表示对话结束。这个约定让「自然收敛」与「预算耗尽」天然可区分：前者是模拟器主动结束，后者是循环先到上限。
备选：由 agent 判断结束（把收敛责任放在被测对象上，无法用于断言它是否啰嗦）。

### D4 按轮切片轨迹，把工具调用挂到轮次上

在每轮开始前后记录轨迹事件数量，切片得到该轮新增的调用。这样「先问后做」可以精确到某轮之前，而不需要全局序号推算。
备选：只保留一条总轨迹（无法判断某次调用发生在哪一轮）。

### D5 回合预算同时是硬上限与判据

预算既防跑飞，也表达「几轮内应该收敛」。自然结束即通过，被预算截断即失败，语义单一不需要额外配置。
备选：预算与判据分开配置（两个相近的旋钮，容易配错）。

## Risks / Trade-offs

- [脚本模拟器过于死板，无法应对 agent 的意外追问] → 这是确定性带来的代价；需要灵活应对时换成自定义模拟器。
- [回合归属依赖切片，若 agent 跨轮保留异步调用会失准] → 明确要求 agent 在单轮内完成其调用；异步场景不属于本能力范围。
- [对话用例增多会让维护成本上升] → 对话用例应聚焦关键路径，与既有各层一样靠数量换覆盖是错误做法。

## Migration Plan

- 新增模型、模块与命令，既有三类用例与协议不变。
- 回滚：移除新增模型与模块，`AnyCase` 恢复为三类。
