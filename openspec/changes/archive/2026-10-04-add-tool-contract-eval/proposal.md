# Proposal

## Why

Agent 项目最常见的线上事故来自工具调用契约被破坏：参数缺失、类型错误、超时、限流重试、非幂等副作用、部分失败未回滚。这类缺陷不需要 LLM 就能确定性复现，但目前缺少可复用的评测载体，只能等线上暴露。先把确定性最强、性价比最高的一层做成平台能力，后续的轨迹、裁判与端到端层才能挂在同一套数据模型上。

## What Changes

- 引入评测平台的最小核心：统一数据模型（Case / Trace / Verdict / Run）、运行结果持久化、确定性断言执行、CLI 与 pytest 集成。
- 新增工具调用契约评测能力，覆盖六类确定性缺陷：必填参数缺失、参数类型错误、调用超时、限流重试、幂等重试、部分失败回滚。
- 提供可复用的故障注入工具桩，使上述六类场景无需真实外部服务即可稳定复现。
- 交付一个可运行的端到端示例，证明「定义用例 → 执行 → 断言 → 落盘 → 查看结果」闭环成立。
- **BREAKING**：无。仓库当前为空，本次为新增能力。

## Capabilities

### New Capabilities

- `eval-core`: 评测运行的最小核心，负责用例、轨迹、判定与运行记录的统一数据模型，确定性断言执行，以及运行结果的持久化与读取。
- `tool-contract-eval`: 工具调用契约的确定性验证，负责声明式契约用例的定义方式与六类失败模式的断言语义。

### Modified Capabilities

无。

## Impact

- 新增 Python 包 `agenteval`、CLI 入口与测试套件；不修改既有代码（仓库当前除 OpenSpec 脚手架外为空）。
- 新增依赖：`pydantic`（数据模型与校验）、`pyyaml`（用例载入）、`pytest`（运行与断言载体）。三者在本机均已可用，`pytest` 需安装。
- 新增运行产物目录 `.agenteval/`，默认写入运行记录，不纳入版本管理。
- 本变更产出的 `eval-core` 规格是后续变更（record/replay、轨迹断言、裁判校准、CI 门禁）的依赖基线。
