# Proposal

## Why

控制台已经能看运行、结论与基线，但四件需要人参与的事仍然只能在命令行完成：给裁判校准准备金标、把外部 agent 的审计导入成轨迹、审核哪些失败值得变成回归用例、以及触发一次运行。前三件事的瓶颈从来不是算法而是操作入口——没有标注界面就没人做校准，没有审核界面就没有人回头看失败。

## What Changes

- 新增金标集标注：上传金标集文件、逐条并排展示两个候选、一键记录偏好、显示标注进度。
- 新增轨迹上传：上传工具调用审计（JSON 或 CSV），导入为命名轨迹，并返回保真度限制。
- 新增失败回流审核：对一次运行执行归因，逐条展示失败与可回流结论，按人工勾选写出候选用例。
- 新增运行触发：选择一个用例文件与工具注册表，从界面触发一次同步运行并跳转到结果。
- 新增操作错误契约：每个操作在失败时返回可读原因并指明对象与位置，而不是笼统失败。
- **BREAKING**：无。既有只读视图不受影响。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `console-actions`: 在既有的结论浏览与基线管理之外，新增金标标注、轨迹上传、失败回流审核与运行触发四类操作，并补充操作错误契约。既有的写操作边界与不可破坏既有产物的约束对新增操作同样适用。

## Impact

- 新增 `agenteval.console.actions` 模块承载四项操作的业务逻辑；`console/server.py` 只负责路由与校验。
- 新增运行根目录下的 `gold/` 与 `cases/` 目录，分别存放金标集与回流产出的候选用例。
- 前端新增标注、回流、导入三个视图，运行视图增加触发入口。
- 依赖无新增；运行触发复用既有运行器，标注复用既有金标模型。
- 运行触发会让浏览器间接执行用户提供的 Python 工厂，与命令行 `--registry` 属同一信任边界，因此同样受回环地址限制。
