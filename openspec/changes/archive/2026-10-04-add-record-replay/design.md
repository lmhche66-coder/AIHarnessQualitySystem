# Design

## Context

- 既有 `eval-core` 提供 Case / Trace / Verdict / Run 与 JSONL 运行存储；`tool-contract-eval` 提供工具协议与六类确定性断言。See proposal.md - Why 了解动机。
- 现有契约用例直接调用真实工具，凡背后有外部服务或模型的工具都无法离线稳定重放。
- 硬约束：回放必须 hermetic。只要回放可能悄悄触达真实工具，「可复现」在 CI 里就是假的。

## Goals / Non-Goals

**Goals:**

- cassette 文件格式与请求指纹稳定，可跨机器重放。
- 相同请求的重复调用按序回放，覆盖重试类场景。
- 回放模式零外部调用，缺失即明确失败。
- 脱敏后仍能正确匹配。
- 轨迹可观察命中与缺失。

**Non-Goals:**

- 不录制 LLM 对话，本变更只覆盖工具交互；模型调用录制留给后续变更。
- 不做 cassette 版本迁移工具与加密存储。
- 不保证并发调用下的消费顺序，v1 只支持单线程顺序消费。
- 不从 cassette 回放耗时相关契约（例如 timeout）。详见 D8。

## Decisions

### D1 cassette 用 JSONL 加 meta 文件，与运行存储同形态

交互逐行追加写入 `<name>.jsonl`，元信息写入 `<name>.meta.json`。录制过程可崩溃安全地追加，回放可流式读取，且与既有 `verdicts.jsonl` 风格一致。
备选：单个 JSON 文件（录制中崩溃会丢失全部内容）；SQLite（v1 引入不必要复杂度）。

### D2 请求指纹用规范化 JSON 的 SHA-256

对 `{target, args}` 做 `sort_keys=True` 与紧凑分隔符的 JSON 编码后取 SHA-256 前 32 位十六进制。稳定、与键序无关、跨机器一致。
备选：`repr()`（键序不稳定、跨版本可能变化）；内置 `hash()`（进程随机化，不可跨机器）。

### D3 同一指纹保存有序响应队列，而非单值映射

限流重试会产生「相同请求、不同响应」，单值映射无法表达。每个指纹维护先进先出序列，回放时按序消费，耗尽即视为缺失。
备选：单值映射（会把重试场景压平，回放结果与录制不一致）。

### D4 回放缺失返回结构化错误而不是抛异常

新增 `ToolErrorKind.CASSETTE_MISS`。用例因此判定为 error，错误信息包含指纹与目标工具，便于区分「agent 多调了一步」与「cassette 过期」。
备选：直接抛异常（会被断言层统一捕获，丢失区分度）。

### D5 指纹基于原始参数，脱敏只作用于落盘

指纹在脱敏前计算，脱敏只影响写入文件的内容。既避免凭据进入仓库，又不影响匹配。
备选：先脱敏再算指纹（两个真实不同、脱敏后相同的请求会撞指纹）。

### D6 严格模式与默认模式分开

默认回放只报告未使用交互；`strict` 开启才判定失败。合法的重试次数波动不应直接让 CI 变红，而「agent 少调用了一步」应由使用者显式开启严格模式来守。
备选：默认严格（初期误报会促使团队绕过门禁，反而更危险）。

### D7 包装器而非改运行器

录制与回放通过包装 `Tool` 实现，`ContractRunner` 与断言层保持不变。这样回放对用例完全透明，也便于后续把同一包装器用到 LLM 客户端上。
备选：在运行器内部分支处理（污染运行器，且无法复用）。

### D8 耗时相关契约在非录制模式下明确拒绝

`timeout` 这类契约的结论取决于真实调用耗时，而 cassette 记录的是请求与响应，回放会把慢调用变成瞬时返回。若放任其继续判定，会得到一个「看起来通过/失败但毫无意义」的结论，这比报错更危险。
因此非录制模式下遇到耗时相关契约，运行器直接产出 error 判定并说明原因；录制模式下不受影响。
备选：回放时按录制的耗时 sleep（会让回放失去提速意义，且录制发生在被放弃的线程上，写入时序不确定）；静默按响应判定（会产生错误结论）。

## Risks / Trade-offs

- [脱敏只覆盖顶层字段] → 在文档中明确边界；嵌套结构内的敏感值需由使用者在工具层处理。
- [并发调用下顺序不确定] → v1 明确只支持单线程顺序消费，并在文档标注。
- [cassette 与真实工具漂移难以察觉] → 严格模式报告未使用交互；后续变更可加入定期重录任务。
- [指纹包含全部参数，冗余参数变化即 miss] → 这是有意的严格行为，避免误匹配；需要宽松匹配时由工具层归一化参数。
- [cassette 体积随交互数增长] → v1 接受，后续变更引入清理与压缩。

## Migration Plan

- 全新能力，无迁移。既有用例在不指定 cassette 时行为不变。
- 回滚：删除 cassette 模块与 CLI 选项即可，既有运行记录格式不受影响。
