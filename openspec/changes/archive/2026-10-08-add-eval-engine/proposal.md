# Proposal

## Why

文章第 6 节把一次评测拆成固定链路：提交评测请求（评测范围 + 评测模式）→ 自动装配数据集 → 并发执行（单条超时、失败重试）→ 采集轨迹与指标 → 结构化评分 → 生成报告。

平台此前只有零散命令：`run` 要手工指定用例文件，`report` 要再手工指定一次运行，范围画像只回答「该装配哪些数据集与指标」，没有「从数据集到用例」的注册表，也没有并发、单条超时、失败重试、异步作业与取消；评测模式、模块级延迟、模型调用次数都只是「声明了但没落数」。评测范围与用例文件之间的最后一公里，以及执行链路上的多处口径，都与文章有出入。

## What Changes

- 新增数据集注册表：把「数据集 → 用例文件」固化成数据，相对路径按注册表文件所在目录解析。
- 新增评测计划：按范围画像装配数据集、用例文件与指标，未注册文件的数据集记为 `missing`。
- 新增 `eval run` 命令：范围 + 评测模式 + 数据集注册表 → 自动装配 → **交给 Agent 执行** → 生成记分卡并写成一条 `report` 结论；引擎按用例类型分派单轮任务与多轮对话，遇到契约/过程用例明确拒收。
- 补齐评测范围：新增「全量评测」（`full`），范围总数达到文章所述的 15 种。
- 执行控制：并发执行、单条用例超时（默认 120s）、失败重试；执行参数与逐用例尝试次数写入运行元数据；使用 cassette 时并发回退到 1。
- **重试口径对齐文章 §6.6**：只对「执行异常」（超时/异常，判为 `error`）重试，默认 2 次、间隔 3 秒；「判定不通过」（`fail`）不重试。
- **运行时指标落数（文章 §6.3）**：把轨迹里的模块信号耗时聚合为意图/规划/记忆注入/检索/工具延迟与端到端延迟；成本栏新增模型调用次数。没有数据的指标不出现在报告里。
- **轨迹感知的裁判（文章 §6.1 步骤 4d）**：新增 `evidence_from_trace`，把命中 Skill、路由、工具调用、检索片段与各段耗时折算成裁判证据；`judge task --run <id>` 把已存运行的轨迹证据一并交给裁判。
- **多轮对话特化（文章 §6.4）**：`dialogue run --turn-settle` 支持每轮结束后等待会话持久化再发起下一轮。
- **用例带输入/期望/Mock（文章 §6.1 步骤 2、4a）**：`CaseAnnotations` 新增可选的 `user_input`、`expected_output`、`expected`、`mock`、`expected_route`；平台捕获并记录 Agent 的最终输出。
- **裁判进引擎（文章 §6.1 步骤 4d）**：`eval run --judge` 按范围自动装配裁判任务，把 Agent 输出 + EvalTrace 交给裁判，逐指标结论并入同一运行记录。
- **平台侧采集（文章 §6.1 步骤 4c）**：工具调用耗时由平台自动测量并计入工具延迟，Agent 无需改代码；无法从平台观测的模块耗时仍由 Agent 上报。
- **异步作业（文章 §6.7）**：新增 `eval submit` / `eval status` / `eval cancel`，提交立即返回 taskId、后台执行、可轮询、可运行中取消；批量并发默认 3 线程。
- **BREAKING**：无。`ContractRunner.run` 新增参数全部可选，默认行为与既有一致。

## Capabilities

### New Capabilities

- `eval-engine`: 数据集自动装配、评测计划、并发/超时/重试执行、运行时指标落数、轨迹感知裁判、异步作业与一次请求直达报告。

### Modified Capabilities

- 无。

## Impact

- 新增 `agenteval.engine` 与 `agenteval.jobs`；`runner` 增加可选执行参数与取消钩子；`scorecard` 增加延迟与模型调用落数；`profiles` 增加全量范围；`models`/`metrics`/`bridge` 贯通模型调用次数；`judge_tasks` 增加轨迹证据；`dialogue` 增加轮次间同步；`cli` 增加 `eval run|submit|status|cancel` 与 `judge task --run`。
- 新增示例数据集注册表 `examples/eval_datasets.json`，示例 agent 上报模型调用次数。
- 依赖无新增；平台不调用任何模型，判定仍由外部提供。
- 不做的事：`eval run` 只驱动文章 §6.1 的 Agent 链路，**不执行**「平台直接调用工具、不经 agent」的契约/过程用例——那类用例属于另一层能力，仍走 `run`；不改门禁与基线口径。
