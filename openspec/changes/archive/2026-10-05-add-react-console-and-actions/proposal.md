# Proposal

## Why

控制台此前是零构建的原生脚本，只读、只展示运行记录。要把它做成真正可用的工作台，需要两件事：一是视图从「单页列表加详情」扩展到运行、结论、基线三类，二是提供第一批操作能力。手写 DOM 拼接撑不起带状态的多视图界面，而基线与人工复核这类操作天生需要交互式界面。

## What Changes

- 前端改用 React 与 Vite，构建产物随包分发；运行时仍然离线可用、不引用任何外部资源。
- 视图分为三类：运行、结论、基线。
- 新增结论视图：列出结论记录，按类型展示门禁、归因与裁判校准的摘要。
- 新增基线视图：列出已有基线及其来源运行与状态分布，并支持把一次运行捕获为命名基线。
- 写接口仅在控制台绑定回环地址时开启；绑定到其它地址时写接口一律拒绝，读接口不受影响。
- 运行详情新增「设为基线」入口。
- **BREAKING**：控制台不再以零构建方式运行，需要 `npm run build` 生成产物；产物已纳入仓库，`pip install` 后开箱可用。

## Capabilities

### New Capabilities

- `console-actions`: 控制台的操作能力边界与首批操作，包括结论浏览与基线管理。

### Modified Capabilities

- `console`: 取消「零构建」的硬性要求，改为「构建产物随包分发、运行时离线可用」；可选写接口的开启条件由「完全不提供写」改为「仅在回环地址提供」。

## Impact

- 新增 `web/` 前端工程（React + Vite），构建输出到 `src/agenteval/console/dist/`。
- `agenteval/console/server.py` 增加结论与基线接口、写操作守卫与产物目录的静态服务。
- 打包配置纳入构建产物；仓库忽略 `web/node_modules/`。
- 新增依赖仅在开发期（构建前端时），Python 运行时依赖不变。
- 本变更让平台第一次具备从界面产生副作用的能力，因此写操作的边界是本变更的重点。
