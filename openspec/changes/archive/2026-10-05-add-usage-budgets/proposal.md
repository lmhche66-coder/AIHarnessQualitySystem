# Proposal

## Why

agent 的成本有两个特点：它会随着多轮与重试线性膨胀，而且膨胀发生在功能判据全绿的时候。现有平台只回答「做对没有」，不回答「代价是多少」——一个用例可能通过，却调用了三十次工具、重试了十次、跑了九十秒。这类问题在功能层面完全隐形。

## What Changes

- 从轨迹推导每次用例的运行指标：工具调用次数、重复调用次数、耗时，并记入判定结果。
- 新增预算判据：用例或任务可以声明最大调用次数、最大重复调用次数、最大耗时，超限即判失败并给出实测值与上限。
- 重复调用次数按「相同目标与相同参数的重复」计，直接对应成本随重试膨胀这一现象。
- 工具结果可以携带 token 用量；系统汇总已报告的用量，且对未报告的用例绝不臆造数字。
- 运行结束产出运行级指标：调用总数、重复调用总数、耗时分位数、token 用量与预算违规清单。
- 预算失败就是普通的判据失败，因此门禁零改动即可覆盖非功能准入。
- **BREAKING**：无。既有用例、运行格式与命令行为不变。

## Capabilities

### New Capabilities

- `usage-budgets`: 从轨迹推导运行指标、声明与评估非功能预算、汇总 token 用量与运行级指标。

### Modified Capabilities

无。运行指标是既有判定与运行记录上的新增字段，预算判据是既有判据族的新成员，都不改变既有需求。

## Impact

- `models.py` 新增 `TokenUsage`、`BudgetCheck`、`CaseMetrics`，并把预算判据加入过程与任务的判据族；`Verdict` 新增可选 `metrics` 字段。
- `tools.ToolResult` 新增可选 `usage` 字段，供承载模型调用的工具上报用量。
- 新增 `agenteval.metrics` 模块承载运行级聚合；预算判据与指标推导放在轨迹层，与既有判据同处一地。
- CLI 的 `run` 与 `task run` 输出增加指标摘要。
- 依赖无新增，分位数用标准库实现。
- 本变更是后续「token 预算」「成本门禁」与「性能回归」的基础。
