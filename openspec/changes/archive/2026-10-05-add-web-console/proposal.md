# Proposal

## Why

平台已经能跑出契约、轨迹、任务、门禁、回流、指标与裁判校准的结果，但这些结果只存在于终端输出与 JSONL 文件里。要看清一次运行到底发生了什么、哪条用例失败、失败在哪个判据、代价多大，得手工翻文件。没有一个统一的查看面，平台的产出就无法被团队真正使用，也无法承接后续的非功能与多端模块。

## What Changes

- 新增本地只读控制台：一个命令启动的 HTTP 服务，读取既有运行产物，不改写任何数据。
- 运行列表按开始时间倒序展示，含用例数、通过/失败/错误计数与开始时间。
- 运行详情逐用例展示判定、失败判据的名称、期望值与实际值，以及错误信息。
- 展示运行级指标、预算违规、任务通过率与 pass@k。
- 可展开查看某条用例的工具调用序列，直接看到轨迹内容。
- 控制台不依赖外部 CDN 与前端构建步骤，离线可用。
- 产物缺失时降级显示，不报错。
- **BREAKING**：无。新命令不影响既有行为。

## Capabilities

### New Capabilities

- `console`: 读取既有运行产物的本地只读展示面，包括运行列表、运行详情、指标与轨迹查看。

### Modified Capabilities

无。控制台只读既有产物，不改变任何既有行为。

## Impact

- 新增 `agenteval.console` 子包，承载服务端与静态资源。
- CLI 新增 `serve` 子命令。
- 打包配置新增静态资源的包数据声明。
- 依赖无新增：服务端用标准库 `http.server`，前端为原生 HTML/CSS/JS，无构建步骤。
- 本变更是后续非功能模块与多端模块的展示承载面：只要它们也产出运行记录，控制台无需改动即可展示。
