# Proposal

## Why

平台已经能把「工具调用对不对、过程可不可控、结果好不好、系统稳不稳」跑成可进 CI 的结论，但结论粒度停在「一次运行有多少用例通过」：所有断言按 AND 汇总成一条通过率，看不出质量、成本、性能三个维度各自的状态，也无法按业务场景定位薄弱环节。

参考 AI Agent 精细化评测体系，评测粒度应更细：一条用例是否通过与某一项指标是否达标应分开——通过与否只看该数据集（或其评测范围）的主指标，其余指标只做诊断；当上游错误（如路由误触发）导致下游指标没有执行机会时，该指标应标记为跳过，既不计入分子也不计入分母。此外，评测范围应能自动装配对应的数据集与指标，而不是靠人工逐个对接。

## What Changes

- 新增评测范围画像：把八个评测数据集、端到端与四个模块级评测范围，以及范围到数据集、数据集到指标的映射固化成配置，给出每个范围的主指标。
- 新增三维记分卡：把一次运行折算成质量、成本、性能三栏，输出指标级通过率、场景通过率与逐用例诊断明细。
- 新增主指标判定：按下达范围解析主指标，通过与否以主指标为准，其余指标仅作诊断，不参与通过判定。
- 新增指标跳过语义：判定结果支持「因上游错误跳过」，被跳过的指标不计入分子也不计入分母，也不再算作失败断言。
- 新增用例归属标注：用例与断言可声明场景、数据集类型与指标标识，运行器把归属透传到判定结果；未标注的既有用例保持原行为。
- 新增 `report` 命令：从既有运行记录构建记分卡，默认按运行元数据解析范围，并像门禁与裁判校准一样把结论落盘。
- **BREAKING**：无。新增字段全部可选，历史运行记录无需改动即可读取。

## Capabilities

### New Capabilities

- `eval-scorecard`: 评测范围画像、三维记分卡、主指标判定与指标跳过语义。

### Modified Capabilities

- `eval-core`: 判定结果与用例新增可选的指标归口、跳过标记与场景/数据集归属字段，且这些字段不改变既有判定行为。

## Impact

- 新增 `agenteval.profiles` 与 `agenteval.scorecard` 两个模块；`models`、`contracts`、`process`、`runner`、`reports` 与 `cli` 做增量改动。
- 新增 `report` 子命令，输出人类可读与 JSON 两种形式，并把记分卡写成 `report` 结论，可被既有只读控制台的结论接口直接读取。
- 依赖无新增；不改运行记录格式的必填约束，历史运行与历史基线不受影响。
- 不做的事：不内置任何模型或裁判，指标的判定仍由外部提供；不改前端控制台资产；不改门禁与基线口径。
