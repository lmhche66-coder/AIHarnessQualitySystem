# Design

## Context

- 既有 `console-actions` 定义了写操作边界、错误语义与运行触发（仅契约与过程用例）。See proposal.md - Why。
- 门禁、裁判校准与任务运行三者都已有命令行实现与结论记录，缺的只是界面入口与编排。

## Goals / Non-Goals

**Goals:**

- 三件「看完结果之后的下一步」可以在界面上完成。
- 结果与命令行一致：门禁与校准写入结论目录，任务运行写入运行记录。
- 复用既有编排，不复制规则。

**Non-Goals:**

- 不做压测触发，仍然刻意保留在命令行。
- 不做后台作业与进度推送，三者都是本地短时操作。
- 不做门禁阈值与校准阈值的可视化编辑，使用既有默认值。

## Decisions

### D1 门禁与校准的结论写入既有结论目录

三者都会产出结论或运行记录。门禁与校准产出的结论与命令行产出的结论落在同一目录、同一结构，因此界面刷新后即可在结论视图看到，不需要为「界面触发的结论」另建视图。
备选：只在响应里返回结果而不落盘（刷新即丢失，且无法事后追溯）。

### D2 未标注样本被跳过而不是拒绝

标注是逐条进行的，中途校准是常见需求。只要有一条已标注样本就允许校准，并在结果中说明跳过了多少；一条都没有时才拒绝。
备选：要求全部标注完成（中途无法校准，且金标集越大越难完成）。

### D3 任务触发与契约触发合并为一个入口

两者只是参数不同：一种给用例文件与注册表，一种给任务集文件、环境工厂与 agent 工厂。合并为一个入口并显式选择模式，界面上只需要一个表单；错误语义也一致。
备选：再开一个入口（界面重复，且两种模式的错误处理要写两遍）。

### D4 显式指定的基线不存在时报错

与命令行一致：没有指定基线时按阈值判定并说明；指定了不存在的基线时说明「比对没发生」比默默按阈值判定更诚实。
备选：回退到阈值判定（使用者会以为比对过了）。

## Risks / Trade-offs

- [界面触发任务集会执行用户提供的 agent 代码] → 与命令行同一信任边界，且受回环地址限制，已在既有边界需求中覆盖。
- [校准耗时随金标集规模增长] → 校准是纯计算，不调用模型（模型由判定器承担），因此本地耗时可忽略。
- [门禁阈值不可在界面调整] → 明确为非目标；需要调参仍走命令行。

## Migration Plan

- 新增三个写入口与界面控件，既有入口不变。
- 回滚：移除新增路由与控件即可。
