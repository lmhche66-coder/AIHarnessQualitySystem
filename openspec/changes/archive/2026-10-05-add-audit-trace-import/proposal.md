# Proposal

## Why

平台已经能从自有运行产出轨迹，但真实 agent 大多跑在别处，工具调用被记在自己的审计日志里。没有一条从外部审计到轨迹的通道，「任意 agent 可接入」就只是设想。kingfar-aiops 就是现成的例子：它的工具调用审计已经包含工具名、参数、生命周期状态、时间戳与耗时，只差一次映射。

## What Changes

- 新增审计轨迹导入能力：把工具调用审计记录（JSON 或 CSV）按开始时间转成平台可求值的轨迹。
- 定义稳定的工具调用事件交换格式，明确哪些字段必需、哪些可选，使外部实现有据可依。
- 映射三态生命周期：完成记为成功，失败记为结构化错误，只有开始没有结束的记录标记为未结束，且不臆造结果。
- 缺失工具名或开始时间的记录被拒绝并指出位置，而不是静默跳过。
- 导入时报告保真度限制：缺少原始返回值时明确标注哪些判据不可评估。
- 新区分「值记录为 None」与「值未记录」：状态传递判据在后一种情况下给出「数据缺失」而非「状态丢失」的结论。
- CLI 新增 `trace import`，导入后即为普通命名轨迹，可直接用于 `run --trace` 与门禁。
- **BREAKING**：无。既有事件写法与判据行为不变。

## Capabilities

### New Capabilities

- `trace-import`: 外部工具调用审计到平台轨迹的导入，包括格式定义、生命周期映射、字段校验与保真度报告。

### Modified Capabilities

- `trace-assertions`: 工具调用归一化需要明确必需与可选字段，并区分「值未记录」与「值记录为空」，使状态传递判据在数据缺失时给出正确归因。

## Impact

- 新增 `agenteval.audit_import` 模块。
- `ToolCall` 增加「值是否被记录」的标记；状态传递判据在值缺失时给出区分性结论。
- `tools.ToolErrorKind` 增加未结束类别，用于表达只有开始没有结束的调用。
- CLI 新增 `trace import` 子命令，支持 JSON 与 CSV。
- 新增来自 kingfar-aiops 审计导出格式的示例文件与端到端用例。
- 依赖无新增，CSV 与 JSON 解析使用标准库。
