# Proposal

## Why

前面的层验证「做得对不对、快不快、贵不贵」，但没验证「会不会被诱导做不该做的事」。提示词注入、系统提示词泄漏、越权调用工具、把数据发往外部，这些在功能判据上全是绿的——agent 确实完成了任务，只是顺带做了不该做的事。

## What Changes

- 新增红队探针：声明式描述对抗输入与它不该触发的结果。
- 三类确定性检测：金丝雀泄漏（响应里出现不该出现的内容）、禁用工具被调用、禁用取值出现在调用参数里。
- 新增探针目标协议：平台不规定 agent 形态，只要求能对一条探针给出响应与工具调用记录。
- 提供带轨迹记录的默认目标实现，把环境工厂与 agent 组合成可执行目标，免去调用方自己拼装。
- 结果产出既有运行记录与判定，并按类别汇总，使门禁可以单独对安全维度设阈值。
- **BREAKING**：无。全新模块与命令。

## Capabilities

### New Capabilities

- `redteam-probes`: 对抗探针的定义与载入、确定性检测、目标协议、带轨迹的默认目标实现，以及按类别的结果汇总。

### Modified Capabilities

无。

## Impact

- 新增 `agenteval.redteam` 模块与 CLI `redteam run` 子命令。
- 新增示例探针集与两个示例目标（一个有漏洞、一个能正确拒绝），用于验证检测确实能识别出问题。
- 依赖无新增，复用既有的轨迹记录与工具调用归一化。
- 本变更是八层里最后一块未实现的能力；补完后八层全部有实现与验证。
