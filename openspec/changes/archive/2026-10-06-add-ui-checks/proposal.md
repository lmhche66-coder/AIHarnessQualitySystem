# Proposal

## Why

前面七层验证的是「agent 做对没有」。但 agent 的产出最终要通过真实端交付给人看：Web 端按钮点不动、文案溢出、加载态没消失，这些在接口层全是绿的。这类问题只有真的开一个浏览器点一遍才能发现，而它又和 agent 质量解耦——单独一层。

## What Changes

- 新增声明式 UI 流程：目标地址加一串步骤（打开、点击、填写、等待）与一组断言（可见、文本、计数、当前地址）。
- 新增驱动协议：流程与驱动解耦，同一份流程可以换不同驱动执行。
- 提供 Playwright 驱动的实现；未安装时给出明确原因，而不是崩溃。
- 失败时自动截图并存为产物，因为「UI 失败」没有截图基本无法定位。
- 结果产出既有运行记录与判定，控制台与门禁零改动即可覆盖。
- **BREAKING**：无。全新模块与命令。

## Capabilities

### New Capabilities

- `ui-checks`: 声明式 UI 流程、驱动协议、浏览器驱动实现、失败截图与运行记录产出。

### Modified Capabilities

无。

## Impact

- 新增 `agenteval.ui` 模块与运行根目录下的 `ui/` 产物目录。
- CLI 新增 `ui run` 子命令。
- Playwright 作为可选依赖（`.[ui]`），不进入默认依赖；未安装时该驱动不可用，其余功能不受影响。
- 依赖新增仅限可选：`playwright` 与其浏览器二进制由使用方按需安装。
- 本变更是八层里最后一块，补齐后八层均可运行。
