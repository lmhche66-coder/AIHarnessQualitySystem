# Design

## Context

- 既有 `eval-core` 已定义统一的用例、轨迹、判定与运行模型，`metrics` 已从轨迹推导运行级指标，`gate` 与 `reports` 已定义门禁与结论落盘。See proposal.md - Why。
- 现状差距有三处：判定按「全部断言通过」汇总，缺少主指标概念；判定结果无法表达「该指标没有执行机会」；缺少按场景与指标归口的聚合视图。
- 硬约束：平台不调用任何模型，指标的判定口径与阈值由外部提供；新增能力必须能读取历史运行，且不改变既有判定结果。

## Goals / Non-Goals

**Goals:**

- 把评测范围、数据集与指标之间的人工对接固化成配置。
- 让「一条用例为何不通过」与「某一项指标是否达标」分开表达。
- 让上游错误不再雪崩式污染所有下游指标。
- 在不改运行记录必填约束的前提下提供质量、成本、性能三维视图。

**Non-Goals:**

- 不内置裁判或评分模型：平台仍只定义指标口径与聚合规则。
- 不改门禁与基线的判定口径：记分卡是并列的诊断视图，不是新的门禁。
- 不改前端控制台：记分卡通过结论接口暴露，界面复用既有的结论浏览。
- 不做评测集自动生成与数据标注界面。

## Decisions

### D1 评测范围画像是一张静态映射，而不是运行期推导

范围到数据集、数据集到指标、范围与数据集到主指标，都固化成模块级常量。这样装配结果可复现、可在测试中断言，也不依赖任何外部状态。
备选：从运行记录里反推范围与指标（运行记录里没有这一层信息，反推会把口径藏进数据里）。

### D2 主指标按「评测模式优先于评测数据集」解析

与文章 5.3 一致：模块级范围关心该模块的核心职责，因此范围级主指标覆盖数据集级主指标；单数据集范围直接取数据集主指标。判定顺序为：执行错误优先，其次看主指标对应的断言，主指标缺失时回落到整体判定。
备选：所有断言取 AND（一个格式问题就能否定内容正确的回答，与文章主张相悖）。

### D3 跳过是断言级标记，聚合时从分子与分母同时剔除

`CheckOutcome.skipped` 表示「因上游错误没有执行机会」。聚合口径与非跳过断言分开：跳过的断言既不计入通过也不计入失败，`failed_checks` 也不再把它列为失败。这样路由错误只体现在路由决策指标上。
备选：把跳过的断言按失败处理（一个模块的错误会雪崩式拉低其他模块的指标）。

### D4 归属标注随用例与断言声明，由运行器透传到判定

用例可声明 `scene` 与 `dataset_type`，断言可声明 `metric`。运行器在构造判定时把归属透传，判定结果自带聚合所需信息，记分卡不需要回读原始用例文件。
备选：记分卡时再配一份用例到归属的映射（多一份需要人工维护的平行配置）。

### D5 新增字段一律可选，判定行为默认不变

`metric`、`skipped`、`scene`、`dataset_type` 都有缺省值。未标注的既有运行照常读取，记分卡在缺失归属时按「未登记指标」与 `unknown` 场景归口，并回落到整体判定。
备选：把归属设为必填（历史运行与既有用例会全部失效）。

### D6 记分卡作为结论落盘，复用既有结论接口

`report` 命令把记分卡写成 `report` 类型的结论记录，与门禁、裁判校准并列。只读控制台的结论接口已经能列出并读取任意结论，因此不需要改前端资产。
备选：为记分卡单独设计一套持久化（与既有结论体系重复）。

## Risks / Trade-offs

- [范围映射表会随指标体系演进而变化] → 映射集中在 `profiles`，并有测试断言「数据集引用的指标必须已登记、主指标必须对该数据集适用」。
- [跳过语义依赖判定方正确标记] → 明确 `skipped` 只表示「没有执行机会」；聚合测试覆盖跳过从分母剔除的行为。
- [三维视图与门禁口径并存可能被误读] → 报告同时给出原始通过率与主指标通过率，并在文本中标注主指标通过率的分母排除了跳过与错误。
- [历史运行不含归属信息] → 记分卡对缺失归属做兜底，历史运行仍可出报告，只是场景粒度较粗。

## Migration Plan

- 新增模块、字段与子命令，既有命令与接口不变。
- 回滚：移除 `report` 子命令与两个新模块，并移除新增的可选字段即可；历史运行记录无需迁移。
